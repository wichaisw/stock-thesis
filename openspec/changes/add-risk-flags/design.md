# Design

## Context

ดู proposal.md - Why

- ป้ายเดิมเป็น dict `{"flag", "reason"}` เช่น `quality.inflection`, `fair_value.history_gap`, `fair_value.structure_change` web แสดงด้วย `Tag` (tone `red` / `violet` / `zinc`) ใน `candidate-table.tsx` และหน้ารายละเอียด
- `PreferredStatements.overlay` เขียนกำไรสุทธิและส่วนผู้ถือหุ้นของ yfinance ทับค่าของ thaifin ใน DataFrame เดียว ค่าของ thaifin หายไปหลัง overlay adapter มี attribute `overlaid` ที่ batch อ่านไป log อยู่แล้ว
- `catalyst.statement_deadlines` ประมาณกำหนดส่งงบจากวันจบไตรมาสปฏิทิน (45 วัน, งบปี 60 วัน) เรียกจาก API ตอนเปิดหน้ารายละเอียดด้วยวันนี้
- backtest เรียก `quality.evaluate` ของ engine ณ แต่ละวันที่ทดสอบ ใช้งบ thaifin อย่างเดียว

## Goals / Non-Goals

**Goals:**
- ป้ายทั้งสามคำนวณใน batch และเก็บใน evaluation ของ run เพื่อให้ list, หน้ารายละเอียด และ history เห็นค่าเดียวกัน
- ป้ายกำไรกระโดดเป็นฟังก์ชันเดียวใน `core/quality.py` ที่ทั้ง batch และ backtest เรียก เพื่อให้ได้ค่าเดียวกันโดยไม่เขียนซ้ำ

**Non-Goals:**
- ไม่ให้ป้ายใดมีผลกับ `candidates.inclusion` หรือ `sort_key`

## Decisions

### D1 ค่าเกณฑ์ทั้งสามอยู่ใน section ใหม่ `flags` ของ `config.yaml`

`flags.profit_jump_ratio: 1.5`, `flags.source_mismatch: 0.15`, `flags.earnings_due_days: 14` ไม่ editable บนเว็บ
- ทางเลือก: กระจายไปตาม section (`quality`, `batch`, `catalyst`) → ไม่เอา ป้ายทั้งสามเป็นเรื่องเดียวกัน (เตือน ไม่คัด) การรวมไว้ทำให้เห็นว่าไม่มีค่าไหนเป็น gate
- ทางเลือก: editable บนหน้า settings → ไม่เอา (out of scope) ต้องแก้ spec `filter-settings` และค่ายังไม่มีหลักฐานว่าควรปรับ

### D2 กำไรกระโดดเทียบ TTM กับ TTM ของ 4 ไตรมาสก่อนหน้านั้น

ใช้ไตรมาสที่รายงานแล้ว (หลังตัดไตรมาสที่งบยังไม่ครบ ตาม requirement เดิม) ต้องมีกำไรสุทธิครบ 8 ไตรมาสล่าสุด TTM = ผลรวม 4 ไตรมาสล่าสุด, TTM ปีก่อน = ผลรวมไตรมาสที่ 5–8 นับจากล่าสุด ติดป้ายเมื่อทั้งสองค่า > 0 และ TTM ≥ ratio × TTM ปีก่อน เหตุผลของป้ายบอกทั้งสองค่าและอัตราส่วน เป็นฟังก์ชัน `quality.profit_jump(reported, ratio)` แยกจาก `quality.evaluate` เพราะ ratio อยู่ใน `cfg.flags` ส่วน `evaluate` รับแค่ `cfg.quality` batch และ backtest เรียกฟังก์ชันนี้ด้วย `cfg.flags.profit_jump_ratio` แล้วเก็บผลที่ `ev["quality"]["profit_jump"]` คู่กับ `inflection`
- ทางเลือก: ให้ `quality.evaluate` รับ `cfg.flags` เพิ่ม → ไม่เอา ต้องแก้ signature ที่ batch, backtest และ test ทุกตัวเรียก เพื่อค่าเดียว
- ทางเลือก: ย้าย ratio ไปไว้ใน `cfg.quality` → ไม่เอา ขัดกับ D1 ที่รวมค่าของป้ายไว้ที่เดียวเพื่อบอกว่าไม่ใช่ gate
- ทางเลือก: ไตรมาสล่าสุด ≥ 2 เท่าของค่าเฉลี่ย 4 ไตรมาสก่อน → ผู้ใช้ไม่เลือก ไวกว่าแต่โดน seasonality
- ทางเลือก: ใช้ `net_profit_yoy` ของไตรมาสล่าสุด → ไม่เอา เป็นไตรมาสเดียว และค่า YoY ของ thaifin ไม่ผ่าน overlay ของ yfinance
- ทางเลือก: TTM ปีก่อน ≤ 0 (พลิกจากขาดทุน) นับเป็นกระโดด → ไม่เอา อัตราส่วนไม่มีความหมาย และกรณีนี้ inflection จับอยู่แล้ว

### D3 adapter เก็บค่าที่ไม่ตรงกันไว้ใน attribute ไม่ใช่คอลัมน์ใหม่

`PreferredStatements` รับ threshold ใน constructor และเก็บ `mismatch: dict[symbol, dict]` เมื่อไตรมาสล่าสุดของแหล่งงบที่ทั้งสองแหล่งมีกำไรสุทธิต่างกัน |yfinance − thaifin| ÷ |thaifin| > threshold โดยเก็บไตรมาส ค่าทั้งสอง และสัดส่วน batch อ่านไปใส่ `ev["source_mismatch"] = {"flag", "reason"}` ทุกหุ้นที่มีงบ (ไม่มีค่าที่เทียบได้ → flag false)
- ทางเลือก: เพิ่มคอลัมน์ `net_profit_base` ใน quarterly → ไม่เอา `QUARTERLY_COLUMNS` เป็นสัญญาของทุกแหล่ง, fakes, backtest cache และ core ต้องรู้จักคอลัมน์ที่มีแค่ batch ใช้
- ทางเลือก: เทียบทุกไตรมาสที่ทับกัน → ไม่เอา ผู้ใช้เลือกไตรมาสล่าสุด และไตรมาสเก่าไม่ได้ใช้ตัดสินแล้ว (ROE TTM ใช้ 4 ไตรมาส แต่ไตรมาสล่าสุดคือตัวที่เพิ่งเปลี่ยน)
- ทางเลือก: ฐานหารเป็นค่าที่ใหญ่กว่า → ไม่เอา ใช้ thaifin เป็นฐานเพื่อให้ "ต่างกัน X%" อ่านเป็นการเปลี่ยนจากค่าเดิมได้ thaifin = 0 ถือว่าเทียบไม่ได้

### D4 งบใกล้ออกคิดจากไตรมาสถัดจากไตรมาสล่าสุดที่รายงานแล้ว และวันที่ราคาของ run

ไตรมาสถัดไป = ไตรมาสล่าสุดที่รายงานแล้ว + 1 กำหนดส่งใช้กฎเดียวกับ `statement_deadlines` (แยกเป็นฟังก์ชันที่ใช้ร่วมกัน) ติดป้ายเมื่อ price_date ≤ กำหนดส่ง ≤ price_date + `earnings_due_days` เก็บที่ `ev["earnings_due"]` พร้อมไตรมาสและวันที่
- ทางเลือก: คิดในเว็บจากวันนี้ → ไม่เอา ต้องเขียนกฎกำหนดส่งซ้ำใน TypeScript และ history ของวันก่อนจะแสดงป้ายตามวันนี้
- ทางเลือก: ใช้กำหนดส่งอย่างเดียวไม่ดูข้อมูล → ผู้ใช้ไม่เลือก ป้ายจะค้างหลังบริษัทส่งงบก่อนกำหนด

### D5 backtest แยก candidate ตามป้ายกำไรกระโดด

แถวของ backtest มี `profit_jump` จาก `quality.evaluate` ตาราง "ป้ายกำไรกระโดด" แสดง candidate ที่ติดป้ายและไม่ติด แยกสองช่วงเดียวกับตาราง variant (excess 63 วัน, CI, t, จำนวนวันที่, จำนวนเฉลี่ยต่อวันที่) และคอลัมน์ "ป้ายมีข้อมูล" เมื่อ excess ของกลุ่มที่ติดป้ายต่ำกว่ากลุ่มที่ไม่ติดในทั้งสองช่วง (ตั้งไว้ก่อนรัน) ผลไม่เปลี่ยน gate
- ทางเลือก: วัดเป็น variant (candidate ที่ตัดหุ้นติดป้ายออก) → ไม่เอา ป้ายไม่ใช่ gate การเทียบสองกลุ่มตอบคำถามตรงกว่าว่าป้ายบอกอะไรหรือไม่

### D6 สีของป้าย

กำไรกระโดดและแหล่งข้อมูลไม่ตรงกันใช้ `red` (ผลอาจผิด) งบใกล้ออกใช้ `zinc` (เหตุการณ์ ไม่ใช่ข้อบกพร่อง) ทุกป้ายมี title เป็นเหตุผล
- ทางเลือก: สีใหม่ (amber) → ไม่เอา เพิ่ม tone ให้ `Tag` เพื่อป้ายเดียว

## Risks / Trade-offs

- [ป้ายเยอะจนไม่มีใครอ่าน] ป้ายแดงเพิ่มจาก 4 เป็น 6 → ตาราง backtest และ task ตรวจ batch รายงานสัดส่วน candidate ที่ติดแต่ละป้าย ถ้าป้ายไหนติดเกินครึ่งให้รายงานผู้ใช้ก่อน archive
- [กำไรกระโดดจับธุรกิจที่ฟื้นจริง] ฐานต่ำปีก่อนให้อัตราส่วนสูงโดยไม่ใช่ one-off → ป้ายไม่คัดหุ้นออก เหตุผลแสดงทั้งสองค่าให้ผู้ใช้ตัดสิน และอาจขึ้นคู่กับ inflection ซึ่งตั้งใจให้เห็นทั้งสองด้าน
- [ปีบัญชีไม่ตรงปฏิทิน] ไตรมาสของ thaifin เป็นไตรมาสบัญชี (AEONTS ปีจบ ก.พ.) กำหนดส่งที่ประมาณจากไตรมาสปฏิทินจึงผิด → ข้อจำกัดเดียวกับ event calendar เดิม ระบุว่าเป็นค่าประมาณใน title ของป้าย
- [แหล่งข้อมูลไม่ตรงกันครอบคลุมน้อย] yfinance มีงบ 5–6 ไตรมาส และข้ามบริษัทที่ไม่ใช่สกุลบาท → ป้ายไม่ติด ≠ ข้อมูลตรงกัน เหตุผลเมื่อไม่ติดไม่แสดง (ไม่ใช่ป้าย "ผ่าน")
- [backtest ไม่ใช่ค่าเดียวกับ batch] backtest ใช้กำไรของ thaifin ซึ่งรวมส่วนผู้ถือหุ้นส่วนน้อยในบางหุ้น (PTT FY22–23) ป้ายกำไรกระโดดย้อนหลังจึงต่างจาก batch ได้ → ข้อจำกัดในไฟล์ผล
- [ผล backtest ของป้ายไม่ครอบคลุม list จริง] backtest ใช้ liquidity ≥ 10 ลบ./วัน และงบ ≥ 12 ไตรมาสจาก `config.yaml` แต่ batch ใช้ค่าบนเว็บ (3 ลบ., 8 ไตรมาส) candidate 19 ต.ค. 2026 อยู่นอกกลุ่มที่ backtest วัด 10/22 ตัว (45%) → ผลของป้ายใช้กับหุ้นเล็กและหุ้นที่งบสั้นไม่ได้ README ต้องระบุข้อนี้ข้างผล การ backtest ด้วยค่าจริงของ batch เป็น change แยก
- [worst case] ป้ายกำไรกระโดดใน batch ไม่ติดหุ้นที่ควรติด เพราะ yfinance ทับไตรมาสล่าสุดแต่ไตรมาส 5–8 มาจาก thaifin คนละนิยาม TTM ปีก่อนจึงสูงหรือต่ำเกินจริง → task ตรวจ batch spot-check หุ้นที่ติดป้ายและหุ้นที่มีป้ายแหล่งข้อมูลไม่ตรงกันเทียบ SET
