# Design

## Context

- "ไตรมาสที่รายงานแล้ว" นิยามเป็น `quarterly[quarterly["eps"].notna()]` แยกกันหลายที่: `core/quality.evaluate`, `core/fair_value.evaluate`, `backtest.excluded` (ตรวจส่วนผู้ถือหุ้นเปลี่ยน), `backtest.cap_gap` และ skill `stock-sanity-check` (`quarterly_flags`)
- `roe_ttm` คืน None เมื่อ 4 ไตรมาสสุดท้ายมีค่าว่าง quality จึงตก ROE ด้วยเหตุผล "ข้อมูลไม่ครบ" และ `no_loss` นับ NaN เป็นไม่มีกำไร
- `current_pe` และ `net_profit_ttm` ใช้ `net_profit.dropna()` อยู่แล้ว peer PE จึงข้ามไตรมาสครึ่งๆ ได้เอง แต่ `eps_ttm` และ band ยังรวมไตรมาสนั้น
- งบ yfinance ถูกทับลงบนงบ thaifin ใน `PreferredStatements` ก่อนถึง core ถ้า yfinance มีกำไรของไตรมาสนั้น ไตรมาสจะครบก่อนถึง helper นี้
- run 36: หุ้นที่ผ่าน liquidity และไตรมาสสุดท้ายมีแค่ EPS มี AEONTS, DIF, RBF, TURBO ทุกตัว EPS > 0 และไตรมาสก่อนหน้าครบ ส่วน 3BBIF ไม่มีกำไรสุทธิเลย 12 ไตรมาส

## Goals / Non-Goals

**Goals:**
- นิยามไตรมาสที่รายงานแล้วที่เดียว ให้ quality, fair value, backtest และ sanity check ใช้ตรงกัน
- ผลตัดสินของหุ้นที่งบครบไม่เปลี่ยนเลย

**Non-Goals:**
- เติมค่าที่ขาดจากแหล่งอื่น หรือเดาค่าจาก EPS × จำนวนหุ้น
- เปลี่ยนการเก็บงบใน DB (แถว EPS-only ยังถูกเก็บตามที่ดึงมา)

## Decisions

### D1: helper เดียวใน `core/quality.py`
เพิ่ม `reported_quarters(quarterly) -> tuple[DataFrame, str | None]` คืนไตรมาสที่มี EPS และไตรมาสที่ไม่นับ (หรือ None) `quality.evaluate` และ `fair_value.evaluate` (ซึ่ง import `roe_ttm` จาก quality อยู่แล้ว) เรียก helper นี้แทน `eps.notna()` ส่วน backtest และ sanity check เรียกตัวเดียวกัน
- ทางเลือกที่ไม่เลือก: (ก) ตัดใน source adapter (`ThaifinFinancials`) ซึ่งจะตัดก่อน yfinance ทับ ไตรมาสที่ yfinance เติมให้ครบได้จะหายไปด้วย และ DB จะไม่มีแถวนั้นให้ตรวจ (ข) แก้แต่ `roe_ttm` และ `no_loss` ให้ข้าม NaN ซึ่งทำให้ quality กับ fair value ใช้ไตรมาสล่าสุดไม่ตรงกัน และ band ยังรวม EPS ของไตรมาสนั้น

### D2: ตัดเฉพาะไตรมาสสุดท้ายไตรมาสเดียว เมื่อไตรมาสก่อนหน้าครบ
เงื่อนไข: แถวสุดท้ายที่มี EPS ขาดกำไรสุทธิหรือส่วนผู้ถือหุ้น และแถวก่อนหน้ามีทั้งสองค่า
- ทางเลือกที่ไม่เลือก: ตัดทุกไตรมาสที่ขาดค่า ซึ่งจะซ่อนช่องว่างตรงกลางที่ spec "ข้อมูล ROE ไม่ครบ" ให้ตก และกองทุนอย่าง 3BBIF จะเหลือ 0 ไตรมาส หรือตัดไตรมาสท้ายต่อเนื่องหลายไตรมาส ซึ่งไม่มีตัวอย่างจริงและอาจทำให้ประเมินด้วยงบเก่าเกินหนึ่งไตรมาส ขัดกับ thesis ที่ถือราวหนึ่งไตรมาส

### D3: EPS ≤ 0 ไม่ตัด
ไตรมาสที่ EPS ติดลบหรือ 0 อาจเป็นไตรมาสขาดทุน ถ้าตัดออก หุ้นจะถูกตัดสินด้วย 4 ไตรมาสก่อนหน้าที่มีกำไร จึงคงพฤติกรรมเดิม (ตก ROE เพราะข้อมูลไม่ครบ)
- ทางเลือกที่ไม่เลือก: ตัดเสมอแล้วติดป้ายเตือน ซึ่งเพิ่ม UI และป้ายไม่ตัดหุ้นออก หุ้นที่อาจขาดทุนจึงยังเข้า list ได้

### D4: บอกไตรมาสที่ไม่นับในเหตุผลของ `min_quarters`
`"มีงบ 55 ไตรมาส (ไม่นับ 2026Q3 ที่ยังมีแค่ EPS)"` เหตุผลนี้แสดงในหน้ารายละเอียดและข้อความ LLM อยู่แล้ว ไม่ต้องแก้ web
- ทางเลือกที่ไม่เลือก: field ใหม่ใน evaluation พร้อมป้ายบนเว็บ ซึ่งเกินความจำเป็นสำหรับหุ้นราว 4 ตัวต่อ run

## Risks / Trade-offs

- [กรณีแย่ที่สุด: EPS ของไตรมาสที่ไม่นับเป็นบวก แต่กำไรสุทธิจริงที่ยังไม่มาติดลบ (เช่น EPS รวมรายการพิเศษหรือคนละนิยามกับกำไรส่วนของบริษัทใหญ่) หุ้นจะผ่านด้วยงบไตรมาสก่อนและอยู่ใน list จนกว่า thaifin จะเติม] → EPS > 0 เป็นสัญญาณกำไรที่ดีพอสำหรับไตรมาสเดียว เหตุผลของ min_quarters บอกไตรมาสที่ไม่นับ และ batch ถัดไปที่ thaifin เติมงบจะประเมินใหม่เอง
- [fair value ของหุ้นพวกนี้ช้าไปหนึ่งไตรมาส] → เหมือนหุ้นที่ยังไม่ส่งงบ ซึ่ง engine ก็ใช้ไตรมาสก่อนอยู่แล้ว
- [backtest: ถ้า cache ของ thaifin มีแถว EPS-only ในอดีต ผลของ method อาจเปลี่ยนเล็กน้อย] → รัน backtest ด้วย cache เดิมแล้วเทียบ ถ้าต่างให้นับจำนวนการประเมินที่เปลี่ยนและบันทึก
