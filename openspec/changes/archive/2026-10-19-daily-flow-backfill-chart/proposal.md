# Proposal

## Why

หน้าประเภทนักลงทุนมีข้อมูลรายวันเฉพาะวันที่ batch เก็บเอง (เริ่ม 14 ต.ค. 2026) จึงยังดูแนวโน้มรายวันไม่ได้ และยังไม่มีกราฟรายวัน ผู้ใช้ขอแหล่งที่มีข้อมูลรายวันย้อนหลังมาวาดกราฟ (15 ต.ค. 2026)

spike แบบอ่านอย่างเดียว (15 ต.ค. 2026) พบว่า:
- InfoQuest (infoquest.co.th) ลงข่าว "สรุปปริมาณการซื้อขายรายกลุ่ม" ทุกวันทำการราว 17:25 น. วันละ 2 ข่าว แยก `(SET)` กับ `(SET+MAI)` ข่าว `(SET)` มีมูลค่าซื้อ, ขาย, สุทธิ ของทั้ง 4 ประเภท หน่วยล้านบาท ทศนิยม 2 ตำแหน่ง และวันที่ของข้อมูลในเนื้อข่าว ("ประจำวันที่ 14 ตุลาคม 2569")
- ข่าววันที่ 14 ต.ค. 2026 ตรงกับ API ของ SET ทุกค่าทั้ง 4 ประเภท (ถึง 0.01 ล้านบาท)
- หน้ารายการ `/tag/investor_type` ย้อนได้ถึง 17 มิ.ย. 2026 (7 หน้า ราว 4 เดือน) robots.txt อนุญาตทั้งหมด เรียกด้วย HTTP ธรรมดาได้ ไม่ต้องใช้ browser
- ryt9.com มีข่าวชุดเดียวกันย้อนถึงปี 2025 แต่หาหน้ารายการไม่เจอ จึงไม่อยู่ใน change นี้

## What Changes

- คำสั่ง CLI ครั้งเดียว (รันซ้ำได้) เติมข้อมูลรายวันย้อนหลังจากข่าว `(SET)` ของ InfoQuest ลงตาราง `investor_flow` เดิม ไม่เขียนทับวันที่ batch เก็บจาก SET เอง
- ก่อนเขียน ตรวจทุกวันที่มีอยู่แล้วจาก SET ว่าค่าของ InfoQuest ตรงกัน ถ้าวันใดไม่ตรงให้ยกเลิกทั้งชุดและไม่เขียนอะไร
- แต่ละแถวระบุแหล่งที่มา หน้าเว็บติดป้าย "InfoQuest" ที่แถวที่เติมย้อนหลัง
- กราฟเส้นมูลค่าสุทธิสะสมรายวันของ 4 ประเภทใต้กราฟรายเดือน (ผู้ใช้เลือกแบบสะสม 15 ต.ค. 2026) นับสะสมจากวันแรกที่แสดง พร้อมปุ่มเปิด/ปิดแต่ละประเภทและค่าเมื่อ hover/focus แบบเดียวกับกราฟรายเดือน
- cross-check เพิ่ม: ผลรวมสุทธิรายวันของ InfoQuest ทั้งเดือน เทียบกับส่วนต่างของจุดในกราฟรายเดือนของ SET และบันทึกผลใน `engine/README.md`

นอกขอบเขต:
- ข้อมูลก่อน 17 มิ.ย. 2026 (ryt9 หรือบริการเสียเงินของ SET) ทำเป็น change แยกถ้าต้องการ
- ใช้ InfoQuest เป็นแหล่งสำรองใน batch เมื่อ SET ดึงไม่ได้
- ตลาด mai และข่าว `(SET+MAI)`
- ใช้ข้อมูลนี้เป็น gate, ตัว sort หรือสัญญาณใน candidate list
- กราฟแท่งสุทธิรายวัน

## Capabilities

### New Capabilities
- (ไม่มี)

### Modified Capabilities
- `investor-flow`: เพิ่ม requirement การเติมย้อนหลังจาก InfoQuest, ป้ายแหล่งที่มา และกราฟสุทธิสะสมรายวัน (เป็น ADDED ทั้งหมด spec หลักของ `investor-flow` จะเกิดเมื่อ archive change `investor-type-flow`)

## Impact

- **engine**: adapter ใหม่ `shortlist/sources/infoquest.py` (ใช้ `urllib` ไม่เพิ่ม dependency), คำสั่ง CLI ใหม่ใน `pyproject.toml` และ `cli.py`, คอลัมน์ `source` ในตาราง `investor_flow`, `GET /investor-flow` รับ `limit` มากขึ้นสำหรับกราฟ
- **web**: กราฟรายวันในหน้า `investor-flow` (ใช้ component กราฟเส้นร่วมกับกราฟรายเดือน), ป้ายแหล่งที่มาในตาราง, field `source` ใน type
- **ข้อมูล**: แถวใหม่ราว 80 วันในตาราง `investor_flow` แถวเดิมไม่เปลี่ยน
- **ความเสี่ยงหลัก**: เป็นการอ่านหน้าข่าว รูปแบบข่าวเปลี่ยนได้ทุกเมื่อ การตรวจก่อนเขียนทำให้ข้อมูลผิดรูปแบบไม่ถูกเก็บ
- **ลำดับ**: ต้อง archive `investor-type-flow` ก่อน archive change นี้ เพราะ delta นี้เพิ่ม requirement ใน spec `investor-flow` ที่เกิดจาก change นั้น (ยังเหลือ task 4.1 ซึ่งรอ cron 2 วันทำการ) implement ได้ก่อน 4.1 เสร็จเพราะไม่แตะ batch แต่แก้ `db.py` และหน้า `investor-flow` ชุดเดียวกัน ไม่กระทบ change อื่นที่ค้างอยู่
