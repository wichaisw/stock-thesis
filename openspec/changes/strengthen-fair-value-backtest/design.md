# Design

## Context

logic ทั้งหมดอยู่ใน `engine/shortlist/backtest.py` (pure) ส่วน `.agents/skills/fair-value-backtest/backtest.py` แค่ดึงข้อมูล cache และเขียนไฟล์ flow ตอนนี้:

```
evaluate_date (ต่อวันที่) --> with_outcomes (ret, max_high ที่ 63 วัน) --> metrics --> report
                                                                         |
                                     groups(): method ละกลุ่ม + median + candidate
                                     excess(): ต่อวันที่ แล้วสรุป mean/median/% บวก
                                     shuffled(): placebo 20 seed
```

engine ไม่มี scipy หรือ numpy เป็น dependency ตรง (มีแค่ผ่าน pandas) รอบ 2026-10-15 ใช้ cache `engine/.cache/fv-backtest/` และ `config.yaml` ที่มี `quality.max_failed_checks: 2` แล้ว ตัวเลขผลของ change นี้ดู proposal.md

## Goals / Non-Goals

**Goals:**
- ตัวเลขเดิมทุกค่าในไฟล์ผล (แถว 63 วัน, bucket, ต่อวันที่) ได้ค่าเท่าเดิมเมื่อใช้ cache เดิม ส่วนใหม่เป็นคอลัมน์หรือตารางที่เพิ่มเข้าไปเท่านั้น
- ไม่เพิ่ม dependency

**Non-Goals:**
- hit rate ที่ 126/252 วัน
- placebo ของตารางต่อระยะ (มีเฉพาะตาราง 63 วัน ทั้งชุดเดิมและชุดไม่นับค่าผิดปกติ)
- hold-out หรือ walk-forward (22 วันที่น้อยเกินจะแบ่ง)

## Decisions

### D1: ช่วงความเชื่อมั่นด้วย bootstrap ข้ามวันที่, t-stat จากสูตรตรง

t-stat = excess เฉลี่ย ÷ (SD ของ excess ต่อวันที่ ÷ √จำนวนวันที่) ช่วงความเชื่อมั่น 95% = percentile 2.5 และ 97.5 ของค่าเฉลี่ยจากการสุ่มวันที่แบบใส่คืน 2,000 รอบ ด้วย `random.Random` seed คงที่ (แบบเดียวกับ placebo) จึงได้ค่าเดิมทุกครั้ง

ทางเลือกที่ไม่เลือก:
- CI แบบ t-distribution ด้วย scipy: เพิ่ม dependency เพื่อค่า quantile ค่าเดียว
- ตาราง t critical เขียนเอง: จำนวนวันที่ต่างกันต่อระยะและต่อกลุ่ม (ราว 18–22) ต้องเก็บหลายค่า เปราะ
- normal 1.96: แคบเกินจริงราว 6% ที่ n ≈ 22 (t = 2.08)

### D2: ระยะวัดผลเป็นคอลัมน์ผลตอบแทนเพิ่ม แล้วคิดตัววัดซ้ำต่อระยะ

`with_outcomes` เติม `ret_126` และ `ret_252` ข้าง `ret` (63 วัน) เดิม ตัววัด excess ต่อระยะใช้ฟังก์ชันเดิมโดยสลับคอลัมน์ผลตอบแทน และ baseline คิดใหม่ต่อระยะจากหุ้นที่ครบระยะนั้น hit ยังคิดที่ 63 วันจาก `max_high` เดิม

ทางเลือกที่ไม่เลือก:
- ตารางผลรวมเต็มชุดต่อระยะ (รวม hit, placebo): ไฟล์ยาวขึ้น 3 เท่า และ hit ที่ระยะยาวต้องนิยามใหม่ ซึ่งไม่ใช่คำถามที่ change นี้ตอบ
- เปลี่ยน `ret` เป็น `ret_63`: แก้ทุกที่ที่อ่าน `ret` และ test เดิมโดยไม่ได้อะไร

### D3: ไม่นับค่าผิดปกติด้วยการกรองแถวของกลุ่ม baseline คงเดิม

ตัดแถวที่ `abnormal` ของ method นั้นออกก่อนจัดกลุ่ม กลุ่ม median, candidate และ candidate (relative) อ่าน flag ของแถว median baseline ยังคิดจากแถว median ทุกแถว ตารางนี้จึงเทียบกับตารางเดิมได้ตรงๆ เพราะต่างกันแค่ว่าใครถูกเลือก fair value > 5× ราคาทำให้ MoS > 80% จึงอยู่ในกลุ่มที่ถูกเลือกเสมอ ส่วน MoS < −100% ไม่เคยถูกเลือก ผลต่างของ excess จึงมาจากฝั่ง fair value สูงเกินเท่านั้น ส่วน bucket ได้ผลจากทั้งสองฝั่ง

ทางเลือกที่ไม่เลือก:
- ตัดหุ้นวันนั้นออกจากทุกอย่างรวม baseline: baseline สองตารางไม่เท่ากัน ผลต่างจะปนกันระหว่างกลุ่มกับ baseline
- winsorize ค่าผิดปกติ: ซ่อนว่าค่าไหนเป็น bug และยังให้ค่าที่ผิดมีน้ำหนักอยู่

### D4: candidate (relative) จัดอันดับจากหุ้นทุกตัวที่มี median MoS แล้วค่อยกรอง quality

ต่อวันที่: rank percentile ของ median MoS ในหุ้นที่มี median MoS ทุกตัว เลือก 20% บน (ค่าคงที่ `RELATIVE_TOP = 0.20` ใน module) แล้วต้องผ่าน quality gate กลุ่มนี้เป็นกลุ่มใหม่ใน `groups()` ข้าง candidate จึงได้ placebo, CI และตารางต่อระยะไปด้วย

ทางเลือกที่ไม่เลือก:
- จัดอันดับเฉพาะหุ้นที่ผ่าน quality: เส้นตัดจะขยับตาม `max_failed_checks` ทุกครั้งที่ปรับ gate ผลจึงปนระหว่างผลของ MoS กับผลของ gate
- ต้องมี MoS > 0 ด้วย: ช่วงที่ตลาดแพง (2021) กลุ่มจะเหลือไม่กี่ตัว และกลับไปมีปัญหาเกณฑ์ absolute ซึ่งเป็นสิ่งที่ต้องการทดสอบ ถ้าผลออกมาดีค่อยทดสอบ floor ใน change ที่ปรับ gate จริง
- top N ตัวต่อวัน: จำนวนหุ้นที่ประเมินได้ลดจาก 261 เป็น 104 N คงที่จึงเลือกสัดส่วนต่างกันมากในแต่ละช่วง

### D5: เพิ่มส่วนในรายงาน ไม่แก้ส่วนเดิม

- ตารางผลรวมเดิม: เพิ่มคอลัมน์ "95% CI" และ "t" ท้ายแถว (แถวสลับ MoS ไม่มี)
- ส่วนใหม่ "ผลรวมแบบไม่นับค่าผิดปกติ": คอลัมน์เดียวกับตารางผลรวม
- ส่วนใหม่ "ต่อระยะวัดผล": กลุ่ม × (63, 126, 252) แสดง excess เฉลี่ย, 95% CI, t, วันที่
- ตาราง bucket: เพิ่มคอลัมน์ median excess 126 และ 252 วัน
- ตารางต่อวันที่: เพิ่มคอลัมน์ candidate % และ relative (จำนวนและ %)
- ข้อจำกัด: เพิ่มข้อช่วงวัดผลซ้อนกันที่ 126/252 วัน และข้อเทียบหลายกลุ่มหลายระยะ
- SKILL.md: เพิ่มแถวในตาราง "Reading the result" สำหรับ CI/t, relative และตารางต่อระยะ

## Risks / Trade-offs

- [กรณีแย่สุด: candidate (relative) หรือ method ใดออกมา CI ไม่คร่อม 0 โดยบังเอิญ แล้วถูกนำไปใช้กับ candidate list จริง เงินจึงถูกจัดตาม noise] → change นี้ไม่แตะ batch ทุกการเปลี่ยน gate เป็น change แยกที่ต้องตอบได้ว่าผลยังอยู่เมื่อดูตารางไม่นับค่าผิดปกติและแถว placebo SKILL.md เขียนให้ถือผลเป็นสมมติฐาน แล้วยืนยันกับผลจริงของ batch ต่อไป
- [เทียบหลายครั้ง: 8 กลุ่ม × 3 ระยะ × 2 ตาราง ราว 48 ช่วง ราว 2 ช่วงจะไม่คร่อม 0 แม้ไม่มี edge] → ข้อจำกัดในไฟล์ผลบอกตรงๆ ตัวตัดสินหลักคือตาราง 63 วันชุดเดิม
- [ช่วงวัดผล 126/252 วันของวันที่ติดกันซ้อนกัน excess ต่อวันที่จึงไม่อิสระ t ดูดีเกินจริง] → ใช้ระยะยาวเป็นตัวประกอบเท่านั้น และระบุในข้อจำกัด
- [bootstrap percentile ที่ n ≈ 20 แคบกว่าจริงเล็กน้อย] → ยอมรับ แสดง t คู่กันให้ตรวจซ้ำได้
- [refactor `metrics` ทำตัวเลขเดิมเปลี่ยนแบบไม่รู้ตัว] → task รันบน cache เดิมแล้วเทียบทุกค่าของตารางเดิมกับไฟล์ 2026-10-15 ต้องเท่ากันทุกตัว
- [รันในวันเดียวกับไฟล์เดิม (15 ต.ค. 2026) จะเขียนทับ `fair-value-2026-10-15.md` รวมส่วน spot-check ที่เขียนด้วยมือ] → ไฟล์เดิม commit แล้ว เทียบกับ `git show HEAD:<ไฟล์>` และคัดส่วน spot-check กลับมาต่อท้ายไฟล์ใหม่
- [252 วันตัดวันที่ท้ายๆ ออก (ราว 4 วันที่) ระยะยาวจึงเห็นแค่ช่วง 2021–2025] → ตารางต่อระยะแสดงจำนวนวันที่ต่อระยะ
- [เวลารันเพิ่มจาก placebo ของตารางไม่นับค่าผิดปกติและ bootstrap] → รอบ cache เดิมใช้ราว 52 วินาที ถ้าเกิน 2 เท่าให้ลดรอบ bootstrap ก่อน
