# Design

## Context

ดู proposal.md - Why สำหรับผลของ spike

สิ่งที่มีอยู่แล้ว (จาก change `investor-type-flow`):
- ตาราง `investor_flow` หนึ่งแถวต่อวัน: `date` (primary key), `total_value`, ซื้อ/ขายของ 4 ประเภท (บาท), `fetched_at` และ `db.investor_flow` คำนวณ `intraday` จาก `fetched_at` เทียบ 17:00 น. ของ `date`
- `db.save_investor_flow` เขียนแบบ `INSERT OR REPLACE` ตาม `date`
- `GET /investor-flow?limit=60` คืนใหม่สุดก่อน หน้า `web/app/investor-flow/page.tsx` ใช้แสดงตาราง
- `web/app/investor-flow/monthly-chart.tsx` เป็นกราฟเส้น SVG ของ 4 ประเภท มีปุ่มเปิด/ปิดและค่าเมื่อ hover/focus
- engine ใช้ `urllib` อยู่แล้วใน `sources/yahoo.py` ไม่มี `requests`

รูปแบบข่าวของ InfoQuest ที่ตรวจแล้ว (ข่าว `2026/663817`):
- หน้ารายการ `https://www.infoquest.co.th/tag/investor_type/page/<n>` (n = 1–7) มีลิงก์ข่าว `https://www.infoquest.co.th/<ปี>/<id>` และชื่อข่าวที่ลงท้ายด้วย `(SET)` หรือ `(SET+MAI)`
- `<meta name="description">` ของข่าวมีตาราง `กลุ่ม มูลค่าซื้อ % มูลค่าขาย % สุทธิ` ของ สถาบันในประเทศ, บัญชีบริษัทหลักทรัพย์, นักลงทุนต่างประเทศ, นักลงทุนในประเทศ หน่วยล้านบาท ทศนิยม 2 ตำแหน่ง
- เนื้อข่าวมี "ประจำวันที่ 14 ตุลาคม 2569"
- ชื่อข่าว `(SET)` ของ 6–12 ต.ค. มีต่างชาติสุทธิ −2,491.60, +1,720.34, −6,361.66, −114.54, +266.90 ล้านบาท ซึ่งสะสมได้เท่ากับ `investor-type-chart?period=5D` ของ SET ที่บันทึกไว้ใน `engine/README.md`

## Goals / Non-Goals

**Goals:**
- เห็นแนวโน้มรายวันของ 4 ประเภทได้ทันทีโดยไม่ต้องรอสะสมหลายเดือน
- ข้อมูลที่เติมผ่านการเทียบกับ SET ก่อนถูกใช้

**Non-Goals:**
- ข้อมูลก่อน 17 มิ.ย. 2026
- ให้ batch ใช้ InfoQuest แทน SET

## Decisions

### D1. อ่านข่าว `(SET)` ด้วย `urllib` จากหน้ารายการ tag แล้วแปลงด้วย pure function

adapter `sources/infoquest.py` เดินหน้ารายการ `/tag/investor_type/page/1..` จนได้ 404 เก็บเฉพาะลิงก์ที่ชื่อข่าวลงท้ายด้วย `(SET)` แล้วเปิดข่าวทีละข่าว เว้น 1 วินาทีระหว่าง request ตั้ง timeout 30 วินาที แปลงเป็น `InvestorFlow` ด้วย pure function ที่อ่านตารางจาก meta description และวันที่จาก "ประจำวันที่ <วัน> <เดือนไทย> <ปี พ.ศ.>" (ปี − 543) มูลค่ารวมคือผลรวมมูลค่าซื้อ ค่าล้านบาทแปลงเป็นบาทด้วย `round(x * 1e6)` ใช้ `InvestorFlow` ตัวเดิม ฟังก์ชันตรวจของ SET จึงใช้ร่วมได้

- ทางเลือกอื่น: Playwright เหมือน SET ปฏิเสธเพราะ HTTP ธรรมดาได้ 200 ไม่ต้องรอ browser
- ทางเลือกอื่น: ค้นด้วย `/?s=` ปฏิเสธเพราะย้อนได้เท่ากันและมีข่าวอื่นปน
- ทางเลือกอื่น: อ่านตารางจาก HTML ของเนื้อข่าว ปฏิเสธเพราะ meta description เป็นข้อความบรรทัดเดียวที่ parse ง่ายกว่า ถ้าวันหนึ่งไม่มี meta การตรวจจะไม่ผ่านและไม่เขียน
- ทางเลือกอื่น: `requests` ปฏิเสธเพราะต้องเพิ่ม dependency ทั้งที่ `urllib` พอ

### D2. คอลัมน์ `source` ในตาราง `investor_flow` เดิม ข้อมูลจาก SET ชนะ

เพิ่ม `source TEXT NOT NULL DEFAULT 'set'` ด้วย `ALTER TABLE` ตอน `db.connect` เมื่อยังไม่มีคอลัมน์ แถวเดิมจึงเป็น `set` การเติมย้อนหลังใช้ `INSERT OR IGNORE` จึงไม่ทับวันที่มีอยู่ ส่วน `save_investor_flow` ของ batch ยังเป็น `INSERT OR REPLACE` จึงทับแถว `infoquest` ได้ `GET /investor-flow` คืน `source` ด้วย

- ทางเลือกอื่น: ตารางแยกแบบที่เคยทำกับ siamchart ปฏิเสธเพราะข้อมูลครบ 4 ประเภทและมีซื้อ/ขายเหมือนกัน ตารางเดียวทำให้กราฟและตารางอ่านที่เดียว
- ทางเลือกอื่น: ไม่เก็บแหล่งที่มา ปฏิเสธเพราะผู้ใช้ต้องรู้ว่าแถวไหนมาจากข่าว และถ้า InfoQuest ผิดภายหลังต้องลบเฉพาะแถวนั้นได้ (`DELETE ... WHERE source = 'infoquest'`)

### D3. ตรวจทั้งชุดก่อนเขียน ไม่ผ่านวันเดียวไม่เขียนเลย

คำสั่งดึงทุกข่าวก่อน แปลงและตรวจทุกวัน (ครบ 4 ประเภท, ผลรวมซื้อกับขายต่างกันไม่เกิน 1%) แล้วเทียบกับทุกวันที่มี `source = 'set'` อยู่แล้ว (ค่าซื้อและขายแต่ละประเภทต่างกันไม่เกิน 0.01 ล้านบาท เพราะข่าวปัดทศนิยม 2 ตำแหน่ง) ผ่านทั้งหมดจึงเขียนใน transaction เดียว ไม่ผ่านให้แสดงวันที่และเหตุผลแล้วจบด้วย exit code ไม่ใช่ 0

- ทางเลือกอื่น: ข้ามวันที่ไม่ผ่านแล้วเขียนวันที่เหลือ ปฏิเสธเพราะวันที่ไม่ตรงกับ SET แปลว่าอาจอ่านผิดทั้งรูปแบบ เขียนบางส่วนจะได้ข้อมูลผิดที่มองไม่เห็น
- ทางเลือกอื่น: ไม่ต้องเทียบกับ SET ปฏิเสธเพราะกฎของโปรเจกต์ให้ cross-check แหล่งใหม่ก่อนใช้ และวันที่เทียบได้มีอยู่แล้ว

### D4. คำสั่ง CLI แยก ไม่อยู่ใน batch

`uv run shortlist-backfill-flow` รันครั้งเดียวหรือรันซ้ำเพื่อเติมวันที่ขาด batch ไม่เรียก เพราะ batch ดึงจาก SET อยู่แล้วทุกวัน

- ทางเลือกอื่น: ให้ batch เติมวันที่ขาดจาก InfoQuest ทุกครั้ง ปฏิเสธในตอนนี้เพราะเพิ่ม request ต่อ batch และผูก batch กับเว็บข่าว เป็น change แยกถ้าต้องการ
- ทางเลือกอื่น: ปุ่มบนเว็บ ปฏิเสธเพราะใช้ครั้งเดียว ดึงราว 90 ข่าวใช้เวลาราว 2 นาที

### D5. กราฟสุทธิสะสมรายวัน ใช้ component กราฟเส้นร่วมกับกราฟรายเดือน

แยกส่วนวาดเส้น แกน ปุ่ม และค่าเมื่อ hover/focus ของ `monthly-chart.tsx` เป็น component กราฟเส้นที่รับจุด (label แกน x, ค่า 4 ประเภท) แล้วใช้กับทั้งสองกราฟ กราฟรายวันคำนวณใน server component: เรียงเก่าสุดก่อน แล้วสะสม `buy − sell` ของแต่ละประเภทจากวันแรก หน้าเรียก `GET /investor-flow?limit=250` ครั้งเดียวใช้ทั้งกราฟ และตารางแสดง 60 วันล่าสุดจากชุดเดียวกัน แกน x เป็นวันทำการที่มีข้อมูลเรียงกัน ไม่เว้นวันหยุด ใต้กราฟบอกช่วงวันที่ จำนวนวัน และว่านับเฉพาะวันที่มีข้อมูล ปุ่มเปิด/ปิดของแต่ละกราฟแยกกัน

- ทางเลือกอื่น: แท่งสุทธิรายวัน ปฏิเสธเพราะผู้ใช้เลือกแบบสะสม (15 ต.ค. 2026)
- ทางเลือกอื่น: คัดลอก `monthly-chart.tsx` เป็นไฟล์ใหม่ ปฏิเสธเพราะสองกราฟจะเพี้ยนจากกันเมื่อแก้ฝั่งเดียว
- ทางเลือกอื่น: แกน x ตามปฏิทินและเว้นวันหยุด ปฏิเสธเพราะเส้นสะสมไม่เปลี่ยนในวันหยุดอยู่แล้ว และต้องมีปฏิทินวันหยุดของ SET

### D6. cross-check ด้วยกราฟรายเดือนของ SET

สุทธิรายเดือนของ SET ได้จากจุดเดือนนั้นลบจุดเดือนก่อนใน `investor_flow_monthly` (ตรวจแล้วใน `investor-type-flow` D5 ว่าตรงกับสุทธิรายเดือนของ settrade) จึงเทียบกับผลรวมสุทธิรายวันของ InfoQuest ทั้งเดือนได้ทั้ง 4 ประเภทโดยไม่ต้องใช้ browser ใช้เดือน ก.ค., ส.ค., ก.ย. 2026 ที่มีข่าวครบเดือน เกณฑ์ต่างกันไม่เกิน 1 ล้านบาทต่อประเภทต่อเดือน (ปัดเศษวันละไม่เกิน 0.005 ล้านบาท × ราว 22 วัน) ผลบันทึกใน `engine/README.md`

## Risks / Trade-offs

- [InfoQuest เปลี่ยนรูปแบบข่าวหรือ meta description (กรณีแย่สุด: ตารางสลับลำดับคอลัมน์ ค่าซื้อกับขายถูกอ่านกลับกันแต่ผลรวมยังตรง)] → การเทียบกับวันที่มีจาก SET จับได้เพราะค่าซื้อกับขายของแต่ละประเภทต้องตรงทุกค่า ถ้ายังไม่มีวันที่เทียบได้ คำสั่งต้องมีอย่างน้อยหนึ่งวันจาก SET จึงจะเขียน
- [ข่าวบางวันหายหรือลงผิดวัน] → วันนั้นขาดจากประวัติ กราฟนับเฉพาะวันที่มีข้อมูลและบอกจำนวนวันใต้กราฟ เส้นสะสมจะขาดค่าของวันนั้นไป
- [ข่าวแก้ไขตัวเลขภายหลัง] → การเติมไม่ทับแถวที่มีอยู่ ถ้าต้องการค่าใหม่ต้องลบแถว `infoquest` แล้วรันใหม่
- [หน้ารายการย้อนได้แค่ราว 4 เดือน และอาจสั้นลงถ้า InfoQuest ตัดรายการ] → รันคำสั่งครั้งแรกเร็วที่สุดหลัง implement หลังจากนั้น batch เก็บเองทุกวัน
- [ข่าวเป็นเนื้อหาของสำนักข่าว] → ใช้คนเดียวบน local เก็บเฉพาะตัวเลข robots.txt อนุญาต ดึงราว 100 request ครั้งเดียวและเว้น 1 วินาที
- [เส้นสะสมเริ่มจากวันแรกที่แสดง ค่าบนกราฟรายวันจึงเทียบกับค่าบนกราฟรายเดือนตรงๆ ไม่ได้] → ใต้กราฟบอกวันเริ่มนับ
