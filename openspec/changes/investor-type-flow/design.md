# Design

## Context

ดู proposal.md - Why สำหรับข้อจำกัดของแหล่งข้อมูล

สิ่งที่มีอยู่แล้ว:
- `batch.execute` เรียก `collect` แล้ว `db.save_run` ที่เขียนผลทั้ง run ใน transaction เดียว และลบผลประเมินของ run ก่อนหน้า (design D3, D4 ของ `value-stock-shortlist`)
- แหล่งข้อมูลอยู่หลัง `Protocol` ใน `shortlist/sources/` (D2) และ `batch.default_sources(cfg)` สร้าง adapter ให้ทั้ง API และ CLI
- ใน browser ของ Orca เรียก `fetch('/api/set/market/SET/investor-type')` จากหน้า set.or.th ได้ ส่วน HTTP client นอก browser ได้ 403 จาก Incapsula
- รูปแบบข้อมูลจาก SET: `asOfDate`, `totalValue` (บาท) และ `investors[]` ที่มี `type` (`institution`, `proprietary`, `foreign`, `individual`), `buyValue`, `sellValue` (บาท)

## Goals / Non-Goals

**Goals:**
- ประวัติรายวันที่สะสมเองและไม่หายเมื่อรัน batch ใหม่
- ถ้าแหล่งข้อมูลใช้ไม่ได้ ส่วนอื่นของ batch ทำงานตามเดิม

**Non-Goals:**
- เติมข้อมูลรายวันย้อนหลัง
- รองรับแหล่งข้อมูลอื่นนอกจาก SET (Protocol เปิดทางไว้แล้วถ้าวันหนึ่งใช้ SETSMART)

## Decisions

### D1. ดึงผ่าน Playwright headless Chromium แล้ว `fetch` จากในหน้า

adapter เปิดหน้า set.or.th ด้วย Chromium แบบ headless รอให้ผ่าน Incapsula แล้วเรียก `fetch('/api/set/market/SET/investor-type')` จากในหน้า (วิธีเดียวกับที่ใช้ใน Orca) แล้วปิด browser ทุกครั้ง แปลงผลเป็นรูปแบบกลาง `InvestorFlow` (วันที่, มูลค่ารวม, ซื้อ/ขายของแต่ละประเภท) ด้วย pure function ที่ test ได้โดยไม่ต้องเปิด browser

- ทางเลือกอื่น: `requests` พร้อม header แบบ browser ปฏิเสธเพราะลองแล้วได้ 403
- ทางเลือกอื่น: ใช้ cookie จาก browser มาใส่ใน `requests` ปฏิเสธเพราะ cookie ของ Incapsula หมดอายุเร็วและต้องมี browser อยู่ดี
- ทางเลือกอื่น: สั่งผ่าน `orca` CLI ปฏิเสธเพราะ cron รันตอนที่ Orca อาจไม่ได้เปิด
- ทางเลือกอื่น: Selenium ปฏิเสธเพราะต้องจัดการ driver เอง ส่วน Playwright ติดตั้ง browser ให้ด้วยคำสั่งเดียว
- ยังไม่รู้ว่า Incapsula ปล่อย headless Chromium ผ่านหรือไม่ จึงเป็น spike เป็นงานแรก ถ้าไม่ผ่านให้หยุดแล้วถามผู้ใช้ ห้ามหาทางหลบการตรวจของ Incapsula

### D2. ตาราง `investor_flow` หนึ่งแถวต่อวัน แยกจากข้อมูลของ run

คอลัมน์: `date` (primary key), `total_value`, ซื้อและขายของแต่ละประเภท (8 คอลัมน์ หน่วยบาท) และ `fetched_at` เขียนแบบ upsert ตาม `date` จึงไม่มีวันซ้ำ และ `save_run` ไม่แตะตารางนี้ ค่าสุทธิคำนวณตอนแสดงผล ไม่เก็บ

- ทางเลือกอื่น: หนึ่งแถวต่อวันต่อประเภท (แบบยาว) ปฏิเสธเพราะทุกการใช้งานอ่านครบ 4 ประเภทของวันเดียวกัน แบบกว้างอ่านง่ายกว่าและตรวจว่าครบ 4 ประเภทได้ด้วย `NOT NULL`
- ข้อมูลระหว่างวันดูจาก `fetched_at` เทียบกับ 17:00 น. ของ `date` (ตลาดปิด 16:30 น. และปิดรอบ ATC ราว 16:40 น.) จึงไม่ต้องมีคอลัมน์เพิ่ม ค่า 17:00 เป็นค่าคงที่ใน code เพราะเวลาปิดตลาดไม่ได้ปรับกันบ่อย

### D3. ขั้นตอนแยกหลัง `save_run` และแยก try/except

`batch.execute` เรียก `record_investor_flow` หลัง `save_run` สำเร็จ ภายใน try/except ของตัวเอง ถ้า error หรือข้อมูลไม่ผ่านการตรวจ ให้ log แล้วจบ สถานะของ run ไม่เปลี่ยน `default_sources` คืน adapter ตัวที่สามเพิ่ม ทั้ง API และ CLI จึงได้ไปพร้อมกัน

- ทางเลือกอื่น: ทำเป็นคำสั่ง CLI แยกที่ตั้ง cron เอง ปฏิเสธเพราะต้องดูแล cron สองตัว และปุ่มรัน batch บนเว็บจะไม่เก็บข้อมูลนี้
- ทางเลือกอื่น: เขียนใน transaction เดียวกับ `save_run` ปฏิเสธเพราะความล้มเหลวของแหล่งข้อมูลนี้จะทำให้ผลประเมินหุ้นไม่ถูกบันทึก
- ทางเลือกอื่น: เก็บ error ไว้ในตาราง `runs` ปฏิเสธเพราะต้องเพิ่มคอลัมน์ในตารางที่ใช้อยู่ log พอสำหรับใช้คนเดียว และหน้าเว็บแสดงวันที่ล่าสุดที่มีข้อมูล ถ้าข้อมูลหายจะเห็นจากวันที่ที่ขาด

### D4. API และหน้าเว็บ

- `GET /investor-flow?limit=60` คืนรายการใหม่สุดก่อน ทุกแถวมี `date`, `total_value`, ซื้อ/ขายของแต่ละประเภท, `fetched_at` และ `intraday` ค่าเป็นบาทเหมือนส่วนอื่นของ API
- หน้า `app/investor-flow/page.tsx` เป็น server component แสดงตารางเป็นล้านบาท ชื่อประเภทเป็นภาษาไทย (สถาบันในประเทศ, บัญชีบริษัทหลักทรัพย์, ต่างชาติ, รายย่อยในประเทศ) ค่าสุทธิเป็นสีเขียวหรือแดง และป้าย "ระหว่างวัน"
- `POST /investor-flow` เรียก `record_investor_flow` ตัวเดียวกับ batch แบบรอผล (ราว 5 วินาที) คืนแถวล่าสุดเมื่อสำเร็จ หรือ 502 พร้อมเหตุผลเมื่อดึงหรือตรวจไม่ผ่าน หน้าเว็บมีปุ่ม "ดึงข้อมูลตอนนี้" เรียกผ่าน server action แล้ว refresh ตาราง (ผู้ใช้ขอเพิ่มตอน apply เพื่อไม่ต้องรัน batch ทั้งตลาดราว 2 นาทีเพื่อข้อมูลชุดเดียว)
  - ทางเลือกอื่น: รันเป็น background task แบบ batch ปฏิเสธเพราะใช้เวลาไม่กี่วินาที รอผลตรงๆ ง่ายกว่าและแสดงเหตุผลที่ล้มได้ทันที
- ลิงก์ไปหน้านี้วางบนหน้า candidates ข้างปุ่ม "ปรับเกณฑ์" ไม่ใส่ใน header (ผู้ใช้เลือกเอาลิงก์ซ้ำซ้อนออกจาก header ใน change `settings-entry-point`)

### D5. กราฟมูลค่าสุทธิสะสมรายเดือน 1 ปี จาก `investor-type-chart?period=1Y` แทน siamchart (ผู้ใช้เลือก 15 ต.ค. 2026)

หน้า settrade.com/th/equities/market-data/historical-report/investor-type ใช้ endpoint นี้ของ SET ได้ 13 จุด (เดือนเดียวกันของปีก่อนถึงเดือนปัจจุบัน) แต่ละจุดมี `date` (วันที่ 1 ของเดือน) และค่าสุทธิสะสมตั้งแต่ต้นช่วงของ `institution`, `proprietary`, `foreign`, `individual` หน่วยบาท ตรวจแล้ว (15 ต.ค. 2026) ว่าจุด ต.ค. ลบจุด ก.ย. ของสถาบันในประเทศได้ +4,377 ล้านบาท ตรงกับสุทธิรายเดือน ต.ค. (+4,376.68) บนหน้าเดียวกัน

- adapter ของ D1 `fetch` ทั้ง `investor-type` และ `investor-type-chart?period=1Y` ในการเปิดหน้าครั้งเดียว แปลงด้วย pure function แยกกัน
- ตรวจก่อนเก็บ: ทุกจุดครบ 4 ประเภท เดือนไม่ซ้ำ และค่าสุทธิ 4 ประเภทรวมกันไม่เกิน ±1 ล้านบาทในทุกจุด (ซื้อรวมเท่ากับขายรวม) ถ้าไม่ผ่านไม่เก็บกราฟชุดนั้น ข้อมูลรายวันกับกราฟตรวจและเก็บแยกกัน อันหนึ่งไม่ผ่านอีกอันยังเก็บได้ และ log ระบุทั้งสองกรณี
- ตาราง `investor_flow_monthly`: `month` (`YYYY-MM`, primary key), ค่าสุทธิสะสม 4 คอลัมน์ (บาท), `fetched_at` เก็บเฉพาะชุดล่าสุด โดยลบของเดิมแล้วเขียนชุดใหม่ใน transaction เดียว เพราะจุดเริ่มสะสมเลื่อนทุกเดือน ค่าของเดือนเดียวกันจากคนละชุดจึงเทียบกันไม่ได้
- `GET /investor-flow/monthly` คืน 13 จุดเก่าสุดก่อนพร้อม `fetched_at` และเป็นรายการว่างเมื่อยังไม่มีข้อมูล
- หน้าเว็บวาดกราฟเส้นด้วย SVG ไม่เพิ่ม library: แกน x เป็นเดือนแบบไทย (ต.ค. 68), แกน y ล้านบาท, เส้นศูนย์, เส้นละประเภทพร้อมสีและชื่อภาษาไทย ปุ่มเปิด/ปิดแต่ละประเภท (`aria-pressed` ใน client component เล็กๆ) และค่าของแต่ละจุดอ่านได้ทั้ง hover และ focus ใต้กราฟบอกว่าเป็นมูลค่าสะสมสุทธิรายเดือนย้อนหลัง 1 ปี พร้อมวันที่ดึง
- ลบของ siamchart ทั้งหมด: adapter, คำสั่ง `shortlist-backfill-flow`, `GET /investor-flow/history`, ตารางค่าสุทธิย้อนหลังบนหน้าเว็บ และเพิ่ม `DROP TABLE IF EXISTS investor_flow_net` ตอน `db.connect`
- ทางเลือกอื่น: เก็บ siamchart ไว้ด้วย ปฏิเสธเพราะผู้ใช้ต้องการเฉพาะแหล่งที่ครบ 4 ประเภท
- ทางเลือกอื่น: กราฟจากข้อมูลรายวันที่เก็บเอง ปฏิเสธในตอนนี้เพราะเริ่มจากเกือบว่าง กราฟรายเดือนเห็นภาพ 1 ปีได้ทันที
- ทางเลือกอื่น: library กราฟ (เช่น Recharts) ปฏิเสธเพราะกราฟเส้น 4 ชุดเขียนด้วย SVG ได้โดยไม่เพิ่ม dependency
- ทางเลือกอื่น: เก็บทุกชุดที่ดึงเป็นประวัติ ปฏิเสธเพราะค่าสะสมต่างฐานกันทุกเดือน และยังไม่มีการใช้งานที่ต้องการ

## Risks / Trade-offs

- [Incapsula บล็อก headless Chromium (กรณีแย่สุด: ผ่านใน spike แต่โดนบล็อกภายหลัง)] → batch ยังทำงานตาม D3 ประวัติขาดเป็นช่วง เห็นได้จากวันที่ที่หายในหน้าเว็บ ถ้าโดนบล็อกถาวร ทางเลือกคือกรอกเองหรือบริการเสียเงินของ SET ซึ่งต้องเป็น change ใหม่
- [SET เปลี่ยนรูปแบบ JSON หรือ path ของ API] → การตรวจข้อมูลก่อนเก็บ (ครบ 4 ประเภท ผลรวมตรงกับยอดรวม) ทำให้ข้อมูลผิดรูปแบบไม่ถูกเก็บ
- [ใช้ API ที่ SET ไม่ได้เปิดให้ใช้อย่างเป็นทางการ] → ดึงวันละครั้งต่อ run ใช้คนเดียวบน local เหมือน thaifin ถ้าจะเปิดให้คนอื่นใช้ต้องเปลี่ยนไปใช้บริการข้อมูลของ SET
- [เสียค่าสุทธิรายวันย้อนหลัง 242 วันจาก siamchart เมื่อลบตาราง (กรณีแย่สุด: วันหนึ่งอยากได้รายวันย้อนหลังคืน)] → ผู้ใช้เลือกแลกแล้ว เอาคืนได้ด้วยการ revert commit แล้วรันคำสั่งเติมย้อนหลังอีกครั้งถ้า siamchart ยังให้ข้อมูล
- [SET เปลี่ยนหรือเลิก `period=1Y`] → กราฟไม่อัปเดตและ log ระบุ ข้อมูลรายวันยังเก็บได้ตามปกติ หน้าเว็บแสดงวันที่ดึงกราฟจึงเห็นว่าเก่า
- [จุดของเดือนปัจจุบันยังไม่จบเดือน] → จุดสุดท้ายคือค่าถึงวันที่ดึง ใต้กราฟแสดงวันที่ดึง
- [Playwright และ Chromium ใช้พื้นที่ ~150 MB และ cron อาจหา browser ไม่เจอเพราะ PATH หรือ HOME ต่างจาก shell ปกติ] → README บอกคำสั่งติดตั้ง และ task ตรวจรันผ่าน cron จริง
- [batch ที่รันระหว่างตลาดเปิดเขียนข้อมูลระหว่างวันแล้วไม่มีรอบหลังปิด] → ติดป้าย "ระหว่างวัน" ตาม D2 cron หลังตลาดปิดจะเขียนทับเป็นค่าปิดตลาด
- [เปิด browser เพิ่มเวลา batch ราว 10–20 วินาที และอาจค้างถ้าเครือข่ายมีปัญหา] → ตั้ง timeout ของการเปิดหน้าและ fetch (30 วินาที) ถ้าเกินให้ถือว่าดึงไม่ได้

## Migration Plan

ตารางใหม่สร้างด้วย `CREATE TABLE IF NOT EXISTS` ตอน `db.connect` เหมือนตารางอื่น และ `DROP TABLE IF EXISTS investor_flow_net` ลบข้อมูล siamchart ไม่ต้องย้ายข้อมูล rollback ด้วยการ revert commit (ข้อมูล siamchart ที่ลบไปแล้วต้องรันคำสั่งเติมย้อนหลังใหม่) ตารางที่เหลือไม่กระทบส่วนอื่น
