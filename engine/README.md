# engine

Python engine: ดึงข้อมูล → ประเมิน → เก็บลง SQLite และเปิด HTTP API ให้ `web/`

```
shortlist/sources/  adapter ของ yfinance และ thaifin (แปลงเป็นรูปแบบกลาง)
shortlist/core/     pure function ของแต่ละ capability
shortlist/batch.py  ประกอบทุกส่วน
shortlist/api.py    FastAPI
scripts/            spike และ backtest
```

## มูลค่าซื้อขายตามประเภทนักลงทุน

`shortlist/sources/set_investor.py` เปิด set.or.th ด้วย Playwright Chromium แบบ headless แล้ว `fetch('/api/set/market/SET/investor-type')` จากในหน้า เพราะ HTTP client ปกติโดน Incapsula ตอบ 403 API นี้ SET ไม่ได้เปิดให้ใช้อย่างเป็นทางการ และให้แค่วันซื้อขายล่าสุด ต้องติดตั้ง browser หนึ่งครั้ง

```sh
uv run playwright install chromium
```

- batch เรียกหลัง `save_run` ทุกครั้ง (CLI และปุ่มบนเว็บ) ถ้าดึงไม่ได้หรือข้อมูลไม่ผ่านการตรวจ (ครบ 4 ประเภท, ผลรวมซื้อและขายต่างจากมูลค่ารวมไม่เกิน 1%) แค่ log run ยังสำเร็จ
- ตาราง `investor_flow` หนึ่งแถวต่อวันตาม `asOfDate` ของ SET ไม่ถูกลบตอน run ใหม่ ประวัติจึงเริ่มจากวันแรกที่รัน
- รันวันเดียวกันซ้ำจะเขียนทับ แถวที่ `fetched_at` ก่อน 17:00 น. (เวลาไทย) ของวันนั้นเป็นข้อมูลระหว่างวัน (`intraday`) ยังไม่ใช่ค่าปิดตลาด
- `GET /investor-flow?limit=60` คืนใหม่สุดก่อน หน่วยบาท
- การเปิดหน้าเดียวกันดึง `investor-type-chart?period=1Y` (ค่าสุทธิสะสมรายเดือน 13 จุด) ด้วย ตรวจแยกจากข้อมูลรายวัน (ครบ 4 ประเภท, เดือนไม่ซ้ำ, ค่าสุทธิ 4 ประเภทรวมกันไม่เกิน ±1 ล้านบาท) ตาราง `investor_flow_monthly` เก็บเฉพาะชุดล่าสุด `GET /investor-flow/monthly` คืนเก่าสุดก่อน

ประวัติรายวันก่อนวันแรกที่เก็บเองเติมจากข่าว "สรุปปริมาณการซื้อขายรายกลุ่ม ...(SET)" ของ InfoQuest (`shortlist/sources/infoquest.py`, HTTP ธรรมดา ไม่ต้องใช้ browser)

```sh
uv run shortlist-backfill-flow   # ราว 3 นาที รันซ้ำได้
```

- ย้อนได้เท่าที่หน้ารายการ `/tag/investor_type` ยังมี (ตอนรันครั้งแรก 15 ต.ค. 2026 ได้ถึง 17 มิ.ย. 2026) InfoQuest ไม่มีข่าวของบางวัน วันนั้นจึงขาด (ดูผลตรวจด้านล่าง)
- แถวมีคอลัมน์ `source` (`set` หรือ `infoquest`) การเติมไม่ทับวันที่มีจาก SET แล้ว ส่วน batch ที่ดึงจาก SET ทับวันจาก InfoQuest ได้ ลบเฉพาะที่เติมได้ด้วย `DELETE FROM investor_flow WHERE source = 'infoquest'`
- ก่อนเขียน คำสั่งเทียบทุกวันที่มีค่าปิดตลาดจาก SET อยู่แล้ว (ซื้อและขายของทุกประเภทต่างไม่เกิน 0.01 ล้านบาท) ถ้าวันใดไม่ตรง หรือไม่มีวันให้เทียบ จะไม่เขียนอะไรเลย แถวระหว่างวันไม่ถูกใช้เทียบเพราะยังไม่ใช่ค่าปิดตลาด

## ค่าเกณฑ์มาจากไหน

batch, CLI (cron) และหน้ารายละเอียดหุ้นใช้ config ชุดเดียวกัน (`load_config(path, db.settings(conn))`) รวมจากสองที่ตามลำดับ

1. `config.yaml` เป็นค่า default ของทุกเกณฑ์
2. ค่าที่แก้บนหน้า settings ของเว็บ เก็บในตาราง `settings` ของ `shortlist.db` เฉพาะช่องที่ต่างจาก default ทับค่าจากข้อ 1 แล้วค่อย validate ทั้งก้อน

ช่องที่ไม่เคยแก้บนเว็บจึงใช้ค่าใหม่ทันทีเมื่อแก้ `config.yaml` ส่วนช่องที่แก้บนเว็บแล้วจะไม่เปลี่ยนตาม YAML จนกว่าจะกด reset บนหน้า settings (ลบ `shortlist.db` ก็ทำให้ค่าที่แก้หายเหมือนกัน) ค่าที่แก้มีผลกับ batch ครั้งถัดไป ไม่เปลี่ยนผลของ run ที่รันไปแล้ว

ช่องที่แก้บนเว็บได้คือช่องที่ติด `editable` ใน `shortlist/config.py` ซึ่งมีชื่อ, tooltip, หน่วยและช่วงค่าอยู่ที่เดียวกัน ส่วนช่องเหล่านี้แก้ได้เฉพาะใน `config.yaml`

- สูตร CDC (`cdc.source`, `ap_length`, `fast_length`, `slow_length`) เพราะต้องตรงกับ TradingView
- `quality.financial_sectors`, ทั้งหมดใน `catalyst` และ `batch`
- ทั้งหมดใน `flags` ซึ่งเป็นเกณฑ์ของป้ายเตือน 2 ป้าย ป้ายเหล่านี้ไม่ตัดหุ้นออก ไม่เปลี่ยนลำดับ และไม่เกี่ยวกับ gate (change `add-risk-flags`)
  - `flags.profit_jump_ratio` (1.5): ป้ายกำไรกระโดด เมื่อกำไรสุทธิ 4 ไตรมาสล่าสุด ≥ 1.5 เท่าของ 4 ไตรมาสก่อนหน้า (ทั้งสองค่าเป็นบวก) กำไรครั้งเดียวดัน ROE TTM ขึ้นและกด PE TTM ลง จึงอาจทำให้ผ่านทั้ง Justified PBV และ peer PE
  - `flags.earnings_due_days` (14): ป้ายงบใกล้ออก เมื่อกำหนดส่งงบที่ประมาณของไตรมาสถัดจากไตรมาสล่าสุดที่มีอยู่ภายใน 14 วันนับจากวันที่ราคาของ run วันที่คิดจากไตรมาสปฏิทิน จึงผิดสำหรับบริษัทที่ปีบัญชีไม่ตรงปฏิทิน

ถ้าค่าที่เคยแก้บนเว็บเป็นช่องที่ไม่มีแล้วหรือถูกเอาออกจาก `editable` engine จะข้ามค่านั้นพร้อม log เตือน batch ไม่ล้ม `scripts/backtest_cdc.py` ใช้แค่ `config.yaml` เพื่อให้ผล backtest ทำซ้ำได้

### ROE และ PE ของ thaifin (task 2.4, 14 ต.ค. 2026)
