# market-data Specification

## Purpose

ดึงและเก็บข้อมูลราคารายวันและงบการเงินรายไตรมาสของหุ้น SET/mai เพื่อเป็นข้อมูลตั้งต้นให้ทุกขั้นของ pipeline คัดหุ้น

## Requirements

### Requirement: Batch ดึงข้อมูลทั้งตลาด
ระบบ SHALL มี batch ที่ดึงรายชื่อหุ้น SET และ mai ทั้งหมดพร้อม sector และราคา OHLCV รายวันย้อนหลังอย่างน้อย 1 ปีของทุกหุ้น และ SHALL ดึงงบการเงินรายไตรมาสเฉพาะหุ้นที่ผ่าน liquidity filter แล้วเก็บลงฐานข้อมูล local

#### Scenario: รัน batch สำเร็จ
- **WHEN** ผู้ใช้สั่งรัน batch และแหล่งข้อมูลตอบปกติ
- **THEN** ฐานข้อมูลมีราคารายวันของทุกหุ้นที่ดึงได้ และงบรายไตรมาสล่าสุดของหุ้นที่ผ่าน liquidity filter และมีบันทึกการรันพร้อมเวลาเริ่ม เวลาจบ และจำนวนหุ้นที่สำเร็จ

#### Scenario: หุ้นไม่ผ่าน liquidity filter
- **WHEN** หุ้นไม่ผ่าน liquidity filter
- **THEN** ระบบไม่ดึงงบของหุ้นนั้น และผลการประเมินระบุว่าไม่ผ่าน liquidity filter

### Requirement: Market cap ย้อนหลัง
ระบบ SHALL ดึงราคาปิดรายวันย้อนหลัง 5 ปี ประวัติ split และจำนวนหุ้นย้อนหลังของหุ้นที่ผ่าน liquidity filter และ SHALL คำนวณ market cap ณ สิ้นแต่ละไตรมาสเป็นราคาปิดจริง (ไม่ปรับตามปันผลหรือ split) × median ของจำนวนหุ้นใน 20 วันทำการสุดท้ายของไตรมาสนั้น (จำนวนหุ้นแต่ละค่ามีผลจนกว่าจะมีค่าใหม่) ไตรมาสที่ไม่มีราคาหรือจำนวนหุ้น SHALL ไม่มี market cap

#### Scenario: หุ้นแตกพาร์
- **WHEN** แหล่งราคาปรับราคาย้อนหลังตาม split 5:1 ที่เกิดหลังสิ้นไตรมาส ทำให้ราคาปิดของไตรมาสนั้นเป็น 5.35 บาท
- **THEN** ระบบถอดการปรับ split ออก ได้ราคาปิดจริง 26.75 บาท แล้วคูณกับจำนวนหุ้นก่อนแตกพาร์

#### Scenario: แตกพาร์กลางไตรมาส
- **WHEN** หุ้นแตกพาร์ 5:1 ช่วงปลายเดือนที่สองของไตรมาส และแหล่งข้อมูลมีจำนวนหุ้นก่อนแตกพาร์ 10 จุดและหลังแตกพาร์ 1 จุดในไตรมาสนั้น
- **THEN** market cap ของไตรมาสนั้นใช้จำนวนหุ้นหลังแตกพาร์ ให้ตรงกับราคาปิดสิ้นไตรมาสซึ่งเป็นราคาหลังแตกพาร์

#### Scenario: จำนวนหุ้นกระโดดจุดเดียว
- **WHEN** จำนวนหุ้นในไตรมาสหนึ่งเป็น 28.56B ทุกจุด ยกเว้นจุดเดียวที่เป็น 29.40B
- **THEN** market cap ของไตรมาสนั้นใช้จำนวนหุ้น 28.56B

#### Scenario: ไม่มีจำนวนหุ้นย้อนหลัง
- **WHEN** แหล่งข้อมูลมีจำนวนหุ้นเริ่มจากไตรมาสหนึ่งเท่านั้น
- **THEN** ไตรมาสก่อนหน้านั้นไม่มี market cap

### Requirement: Trigger ได้ทั้งแบบตั้งเวลาและแบบ manual
ระบบ SHALL ให้รัน batch ได้ทั้งจาก command line (ใช้กับการตั้งเวลา) และจากปุ่มใน UI และ SHALL ไม่ยอมให้มี batch รันซ้อนกันมากกว่า 1 ตัว

#### Scenario: กดรันจาก UI
- **WHEN** ผู้ใช้กดปุ่มรันใน UI ขณะไม่มี batch ทำงานอยู่
- **THEN** batch เริ่มทำงาน และ UI แสดงสถานะว่ากำลังรัน

#### Scenario: กดรันซ้ำขณะ batch ยังทำงานอยู่
- **WHEN** ผู้ใช้สั่งรันขณะมี batch ทำงานอยู่แล้ว
- **THEN** ระบบไม่เริ่ม batch ใหม่ และแจ้งว่ามี batch กำลังรันอยู่

### Requirement: หุ้นแต่ละตัว fail ได้โดยไม่ล้มทั้ง batch
ระบบ SHALL แยก error ของหุ้นแต่ละตัว ถ้าดึงข้อมูลหุ้นตัวใดไม่ได้ batch SHALL ทำหุ้นตัวอื่นต่อจนจบ และบันทึกชื่อหุ้นที่ fail พร้อมเหตุผล ยกเว้นเมื่อหุ้น fail ด้วย error ของเครือข่าย (เช่น resolve ชื่อ host ไม่ได้, เชื่อมต่อไม่ได้, timeout หรือแหล่งราคาไม่มีข้อมูลของหุ้นขณะที่เชื่อมต่อแหล่งราคาไม่ได้) ติดกันครบจำนวนใน config (default 5 ตัว) batch SHALL หยุดและบันทึก run เป็น failed พร้อมเหตุผลว่าเครือข่ายใช้ไม่ได้และ error ล่าสุด หุ้นที่ fail ด้วยเหตุผลอื่นหรือดึงได้สำเร็จ SHALL ทำให้การนับติดกันเริ่มใหม่

#### Scenario: แหล่งงบการเงินพังกับหุ้นบางตัว
- **WHEN** ดึงงบของหุ้นตัวหนึ่งแล้วเกิด error
- **THEN** batch จบได้ตามปกติ หุ้นตัวนั้นถูกบันทึกเป็น fail พร้อมข้อความ error และหุ้นตัวอื่นยังได้รับการประเมิน

#### Scenario: ไม่มีราคาของหุ้นบางตัว
- **WHEN** แหล่งราคาไม่มีข้อมูลของหุ้นตัวหนึ่ง
- **THEN** หุ้นตัวนั้นถูกบันทึกเป็น fail ด้วยเหตุผลว่าไม่มีข้อมูลราคา

#### Scenario: เครือข่ายล่มระหว่างรัน
- **WHEN** ดึงงบของหุ้น 5 ตัวติดกันแล้วได้ error ว่า resolve ชื่อ host ไม่ได้
- **THEN** batch หยุดโดยไม่ดึงหุ้นตัวที่เหลือ run ถูกบันทึกเป็น failed พร้อมเหตุผลว่าเครือข่ายใช้ไม่ได้ และ candidate list ยังแสดงผลของ run ที่สำเร็จครั้งก่อน

#### Scenario: เครือข่ายล่มตั้งแต่ดึงรายชื่อหุ้น
- **WHEN** ดึงรายชื่อหุ้นแล้วได้ error ของเครือข่าย
- **THEN** batch หยุดทันที run ถูกบันทึกเป็น failed พร้อมเหตุผลว่าเครือข่ายใช้ไม่ได้และดึงรายชื่อหุ้นไม่ได้ เหมือนกรณีหุ้น fail ติดกัน

#### Scenario: เครือข่ายล่มช่วงดึงราคา
- **WHEN** ช่วงดึงราคา หุ้น 5 ตัวติดกันไม่ได้ราคา และเชื่อมต่อแหล่งราคาไม่ได้
- **THEN** batch หยุดและบันทึก run เป็น failed เหมือนช่วงดึงงบ

#### Scenario: ไม่มีราคาแต่เครือข่ายใช้ได้
- **WHEN** หุ้น 8 ตัวไม่ได้ราคา และเชื่อมต่อแหล่งราคาได้
- **THEN** batch ทำต่อ หุ้นทั้ง 8 ตัวถูกบันทึกเป็น fail ด้วยเหตุผลว่าไม่มีข้อมูลราคาตามเดิม และไม่นับเป็น error ของเครือข่าย

#### Scenario: ไม่ได้ market cap ตอนเครือข่ายล่ม
- **WHEN** หุ้นที่ผ่าน liquidity ได้ประวัติราคาสำหรับ market cap ว่าง และเชื่อมต่อแหล่งราคาไม่ได้
- **THEN** หุ้นนั้นถูกบันทึกเป็น fail ด้วยเหตุผลว่าดึง market cap ไม่ได้ และนับเป็น error ของเครือข่าย ไม่ถูกประเมินโดย band เป็น N/A

#### Scenario: ไม่ได้ market cap แต่เครือข่ายใช้ได้
- **WHEN** หุ้นที่ผ่าน liquidity ได้ประวัติราคาสำหรับ market cap ว่าง และเชื่อมต่อแหล่งราคาได้
- **THEN** หุ้นนั้นถูกประเมินต่อโดยเกณฑ์ที่ต้องใช้ market cap เป็น N/A ตามเดิม

#### Scenario: error ของเครือข่ายสลับกับหุ้นที่ไม่มีอยู่
- **WHEN** หุ้น 4 ตัวติดกัน fail ด้วย error ของเครือข่าย ตัวที่ 5 fail ด้วยเหตุผลว่าไม่พบหุ้น แล้วอีก 4 ตัวถัดไป fail ด้วย error ของเครือข่าย
- **THEN** batch ไม่หยุด เพราะไม่มีครั้งไหนที่ error ของเครือข่ายติดกันครบ 5 ตัว

### Requirement: Clean ข้อมูลที่ยังไม่สมบูรณ์
ระบบ SHALL ตัดแถวราคารายวันที่ไม่มีราคาปิดทิ้งก่อนใช้งาน และ SHALL ถือว่าไตรมาสล่าสุดของงบคือไตรมาสล่าสุดที่มี EPS ไม่ใช่แถวล่าสุดที่แหล่งข้อมูลส่งมา

#### Scenario: แถวราคาล่าสุดไม่มีราคาปิด
- **WHEN** แถวราคาวันล่าสุดมี open/high/low แต่ราคาปิดว่าง
- **THEN** ระบบไม่ใช้แถวนั้น และใช้วันก่อนหน้าที่มีราคาปิดเป็นวันล่าสุด

#### Scenario: แหล่งงบมีแถวไตรมาสล่วงหน้า
- **WHEN** ข้อมูลงบมีแถวไตรมาสที่มีแค่ราคาหรือ ratio แต่ไม่มี EPS
- **THEN** ระบบใช้ไตรมาสล่าสุดที่มี EPS เป็นงบล่าสุด

### Requirement: เปลี่ยนแหล่งข้อมูลได้
ระบบ SHALL ให้ส่วนประเมินหุ้นใช้ข้อมูลในรูปแบบกลางที่ไม่ผูกกับแหล่งข้อมูลใดแหล่งหนึ่ง เพื่อให้เปลี่ยนแหล่งข้อมูล (เช่น ไปใช้ SETSMART) ได้โดยไม่ต้องแก้ logic การประเมิน

#### Scenario: เปลี่ยนแหล่งงบการเงิน
- **WHEN** แหล่งงบการเงินถูกเปลี่ยนไปใช้แหล่งใหม่ที่ส่งข้อมูลในรูปแบบกลางเดียวกัน
- **THEN** ผลการประเมินหุ้นคำนวณได้เหมือนเดิมโดยไม่ต้องแก้ส่วนประเมิน

### Requirement: Dividend yield 12 เดือนรายไตรมาส
ระบบ SHALL คำนวณ dividend yield 12 เดือนของแต่ละไตรมาสในกรอบ 5 ปีของหุ้นที่ผ่าน liquidity filter เป็นผลรวมปันผลเงินสดต่อหุ้นที่ขึ้น XD ใน 12 เดือนก่อนสิ้นไตรมาส ÷ ราคาปิดสิ้นไตรมาส โดยทั้งปันผลและราคาอยู่บนฐานจำนวนหุ้นเดียวกัน ปันผลเป็นหุ้น SHALL ไม่นับเป็นปันผลเงินสด ระบบ SHALL ไม่ใช้ dividend yield จากแหล่งงบการเงิน

#### Scenario: จ่ายปันผลปีละสองครั้ง
- **WHEN** หุ้นขึ้น XD ปันผลเงินสด 0.80 และ 1.30 บาทภายใน 12 เดือนก่อนสิ้นไตรมาส และราคาปิดสิ้นไตรมาสคือ 35.00 บาท
- **THEN** dividend yield 12 เดือนของไตรมาสนั้นคือ 2.10 ÷ 35.00 = 6.0%

#### Scenario: ไตรมาสที่ไม่มี XD
- **WHEN** ไตรมาสหนึ่งไม่มี XD แต่มี XD ปันผลเงินสดใน 12 เดือนก่อนหน้า
- **THEN** dividend yield 12 เดือนของไตรมาสนั้นนับปันผลที่ XD ใน 12 เดือนก่อนหน้า ไม่เป็นศูนย์

#### Scenario: ปันผลเป็นหุ้น
- **WHEN** หุ้นจ่ายปันผลเป็นหุ้นอัตรา 5:1 พร้อมเงินสด 0.0093 บาทต่อหุ้น
- **THEN** dividend yield 12 เดือนนับเฉพาะเงินสด 0.0093 บาท และหุ้นปันผลไม่ถูกนับเป็น yield

#### Scenario: แตกพาร์หลัง XD
- **WHEN** หุ้นขึ้น XD ปันผลเงินสด 1.00 บาท ที่ราคาปิด 20.00 บาท แล้วแตกพาร์ 2:1 ในภายหลัง
- **THEN** dividend yield 12 เดือนของไตรมาสที่ XD คือ 5.0% เท่ากับก่อนแตกพาร์

#### Scenario: ไม่มีปันผลเงินสดเลย
- **WHEN** หุ้นไม่มี XD ปันผลเงินสดในกรอบ 5 ปี
- **THEN** dividend yield 12 เดือนของทุกไตรมาสเป็นศูนย์

### Requirement: เวลารวมสูงสุดของ batch
ระบบ SHALL หยุด batch และบันทึก run เป็น failed เมื่อใช้เวลารวมเกินค่าใน config (default 20 นาที) พร้อมเหตุผลที่บอกเวลาที่ใช้และช่วงที่กำลังทำ ระบบ SHALL ตรวจเวลาระหว่างหุ้นแต่ละตัว จึงอาจเกินเพดานได้ไม่เกินเวลาของการดึงข้อมูลหุ้นหนึ่งตัว

#### Scenario: batch ช้าเกินเพดาน
- **WHEN** batch ทำงานครบ 20 นาทีขณะยังดึงงบไม่ครบ
- **THEN** batch หยุดก่อนดึงหุ้นตัวถัดไป run ถูกบันทึกเป็น failed พร้อมเหตุผลว่าใช้เวลาเกิน 20 นาทีระหว่างช่วงดึงงบ และ candidate list ยังแสดงผลของ run ที่สำเร็จครั้งก่อน

#### Scenario: batch ปกติ
- **WHEN** batch ทำงานเสร็จใน 3 นาที
- **THEN** run ถูกบันทึกเป็น succeeded ตามเดิม

### Requirement: Log ระยะเวลาของแต่ละช่วง
ระบบ SHALL บันทึก log ของ batch พร้อมเวลา และ SHALL บันทึกระยะเวลาเมื่อจบแต่ละช่วง ได้แก่ ดึงรายชื่อหุ้น, ดึงราคา, ดึงงบและ market cap และประเมิน ทั้งเมื่อรันจาก command line และจาก UI

#### Scenario: ตรวจย้อนหลังว่าช่วงไหนช้า
- **WHEN** batch รันเสร็จหรือถูกหยุด
- **THEN** log มีเวลาของแต่ละบรรทัด และระยะเวลาของทุกช่วงที่ทำเสร็จ

### Requirement: ตรวจหุ้นที่ราคาไม่อัปเดต
ระบบ SHALL ติดป้ายราคาไม่อัปเดตให้หุ้นที่ประเมินได้ซึ่งวันที่ของแท่งราคาล่าสุดเก่ากว่าวันที่ราคาของ run (วันที่ราคาล่าสุดในบรรดาหุ้นทุกตัวที่ประเมินได้ใน run นั้น) และ SHALL ให้ผลของ run ที่สำเร็จล่าสุดมีจำนวนหุ้นที่ราคาไม่อัปเดตกับวันที่ราคาที่พบบ่อยที่สุดในกลุ่มนั้น ป้ายนี้ SHALL ไม่ตัดหุ้นออกจาก candidate list และไม่ใช้เรียงลำดับ

#### Scenario: หุ้นส่วนใหญ่ขาดแท่งล่าสุด
- **WHEN** run ประเมินหุ้นได้ 922 ตัว มี 25 ตัวที่แท่งล่าสุดเป็นวันที่ 14 ต.ค. และ 897 ตัวเป็นวันที่ 12 ต.ค.
- **THEN** วันที่ราคาของ run คือ 14 ต.ค. หุ้น 897 ตัวติดป้ายราคาไม่อัปเดต และ run มีจำนวนหุ้นที่ราคาไม่อัปเดต 897 ตัว วันที่ 12 ต.ค.

#### Scenario: ราคาอัปเดตครบ
- **WHEN** หุ้นทุกตัวที่ประเมินได้มีแท่งล่าสุดเป็นวันเดียวกัน
- **THEN** ไม่มีหุ้นตัวไหนติดป้ายราคาไม่อัปเดต และจำนวนหุ้นที่ราคาไม่อัปเดตของ run เป็น 0

#### Scenario: หุ้นที่ราคาไม่อัปเดตแต่ผ่านทุก gate
- **WHEN** หุ้นติดป้ายราคาไม่อัปเดตและผ่านทุกเงื่อนไขของ candidate list
- **THEN** หุ้นยังอยู่ใน candidate list ในลำดับเดียวกับเมื่อไม่มีป้าย

### Requirement: กำไรสุทธิและส่วนผู้ถือหุ้นจากแหล่งราคาก่อน
ระบบ SHALL ใช้กำไรสุทธิและส่วนผู้ถือหุ้นของบริษัทใหญ่รายไตรมาสจากแหล่งราคา (yfinance) ก่อน และ SHALL ใช้ค่าจากแหล่งงบ (thaifin) เฉพาะไตรมาสหรือ field ที่แหล่งราคาไม่มีค่า field อื่นของงบรายไตรมาส SHALL มาจากแหล่งงบเหมือนเดิม

#### Scenario: แหล่งราคามีงบ 5 ไตรมาสล่าสุด
- **WHEN** แหล่งราคามีกำไรสุทธิและส่วนผู้ถือหุ้นของ 2Q25–2Q26 และแหล่งงบมีย้อนหลัง 5 ปี
- **THEN** ไตรมาส 2Q25–2Q26 ใช้ค่าจากแหล่งราคา และไตรมาสก่อน 2Q25 ใช้ค่าจากแหล่งงบ

#### Scenario: แหล่งราคาไม่มีค่าบางไตรมาส
- **WHEN** แหล่งราคาไม่มีส่วนผู้ถือหุ้นของ 1Q26 แต่มีกำไรสุทธิ
- **THEN** ส่วนผู้ถือหุ้นของ 1Q26 ใช้ค่าจากแหล่งงบ และกำไรสุทธิของ 1Q26 ใช้ค่าจากแหล่งราคา

### Requirement: งบที่ไม่ใช่สกุลบาท
ระบบ SHALL ไม่ใช้งบจากแหล่งราคาของบริษัทที่แหล่งราคาระบุว่ารายงานงบเป็นสกุลเงินอื่นที่ไม่ใช่บาท หรือไม่ระบุสกุลเงิน และ SHALL ใช้ค่าจากแหล่งงบทั้งหมดแทน

#### Scenario: บริษัทรายงานงบเป็น USD
- **WHEN** แหล่งราคาระบุว่าบริษัทรายงานงบเป็น USD
- **THEN** กำไรสุทธิและส่วนผู้ถือหุ้นทุกไตรมาสมาจากแหล่งงบ

### Requirement: ดึงงบจากแหล่งราคาไม่ได้
ระบบ SHALL ใช้ค่าจากแหล่งงบทั้งหมดเมื่อดึงงบจากแหล่งราคาไม่ได้หรือได้ข้อมูลว่าง และ SHALL ไม่นับเป็นหุ้นที่ fail

#### Scenario: แหล่งราคาตอบ error ตอนดึงงบ
- **WHEN** แหล่งราคาตอบ error ตอนดึงงบของหุ้นหนึ่ง แต่แหล่งงบตอบปกติ
- **THEN** หุ้นนั้นถูกประเมินด้วยค่าจากแหล่งงบทั้งหมด และไม่อยู่ในรายการหุ้นที่ fail
